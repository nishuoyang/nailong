## 三、根因分析

### 直接原因

`server/prisma/schema.prisma` 中数据库连接写死：

```prisma
datasource db {
  provider = "sqlite"
  url      = "file:./data.db"   // ❌ 硬编码
}
```

- 该写法完全**忽略** `process.env.DATABASE_URL`（`docker-compose.prod.yml` 注入的 `file:/app/data/data.db` 始终无效）
- Prisma 相对路径按 **schema.prisma 所在目录**解析 → 实际打开的是 **`/app/prisma/data.db`**（位于镜像内，非卷）
- `docker-compose.prod.yml` 声明的 `sqlite_data:/app/data` 数据卷**从未被使用**

### 数据为何丢失

- 7-8 月期间用户上传的图片记录全部写入**旧容器可写层**的 `/app/prisma/data.db`（容器内文件系统，无持久化）
- `docker compose up -d --build` 重建容器时，旧容器被删除 → **可写层一并销毁**，且无法找回（已确认 `/var/lib/docker`、`/var/lib/containerd` 均无残留）
- 同名数据卷 `minio_data`（图片文件）与 `redis_data`（旧缓存）保留完好 → 呈现"图片还在、记录全无"的表象

### 关键佐证

1. 新容器 `/app/data/data.db` 仅 172 字节（Prisma 初始化的空库）
2. `find / -name "data.db"` 找到的 92KB 副本均为 0 图片、缺 `created_at` 列的**旧版开发库**（早早被打包进旧镜像）
3. 旧容器 rootfs（`/var/lib/docker/rootfs/overlayfs/<id>/app/prisma/data.db`）存在，但只是镜像层 COPY 的快照，非增长后的生产库
4. 容器内 `ps`/`/proc/<pid>/fd` 确认 node 进程打开的始终是 `/app/prisma/data.db`

## 四、恢复方案

### 可利用的资产

| 资产 | 状态 |
|---|---|
| MinIO 卷 `nailonghub_minio_data` | ✅ 25 组图片完整（原图 + `_thumb_md` + `_thumb_sm`） |
| Redis 卷 | ✅ 仅缓存，无业务数据 |
| SQLite 数据库 | ❌ 记录丢失（可重建） |

### 执行步骤

1. **修复 schema**：`url = env("DATABASE_URL")`，使迁移/seed/运行时统一读写数据卷 `/app/data/data.db`
2. **重建数据库**：移除旧 schema 库文件 → 新容器启动自动 `prisma migrate deploy` + `seed.js`（管理员 `admin@nailong.com / admin123`）
3. **重建图片记录**（`server/scripts/rebuild_images.py`）：
   - 扫描 MinIO 卷原图文件（排除 `_thumb_*`）
   - URL 前缀 `/minio/nailong-images/`（同源代理），配对缩略图
   - 归属管理员、`status=approved`、`section=general`
   - `created_at` 取文件名 13 位毫秒时间戳
4. **清空 Redis 旧缓存**（`flushdb`），避免旧 `daily_recommendation` 指向不存在的 id

### 过程中踩到的两个坑（均已修复）

| 问题 | 修复 |
|---|---|
| Prisma 报 `Conversion failed: input contains invalid characters` | Python `sqlite3` 写入的日期是空格格式 `2026-07-15 09:06:25`，Prisma SQLite 要求 ISO 8601（`2026-07-15T09:06:25.467000Z`）→ 脚本改为 ISO 并自动修复存量数据 |
| 日期修复循环只生效 1 条 | Python sqlite3 迭代未结束就执行 UPDATE 会提前终止游标迭代 → 先 `fetchall()` 再逐行 UPDATE（`08078b5`） |

## 六、教训与预防措施

1. **数据库连接必须走环境变量**，且**启动时校验实际连接目标**（本次若 entrypoint 在启动时打印 `PRAGMA database_list` 或目标文件路径，第一时间就能发现连错了库）
2. **生产数据必须持久化**：SQLite 等文件型数据库永远放在数据卷或 bind mount 上，禁止依赖容器可写层
3. **迁移/seed 与运行时目标库必须一致**：`entrypoint.sh` 的 `prisma migrate deploy` 与 `PrismaClient` 使用同一 `DATABASE_URL`（本次修复后统一）
4. **任何 `up -d --build` / 重建前先备份数据库**：
   ```bash
   docker compose -f docker-compose.prod.yml cp server:/app/data/data.db ./backup-$(date +%F).db
   ```
5. **数据分层存储的价值**：图片（MinIO 卷）与元数据（SQLite）分离，单边损坏时可从另一边恢复
6. **迁移文件与 schema 一致性**：改 schema 必须配套 `prisma migrate dev` 生成迁移，且服务器 `migrate deploy` 结果需人工确认
